# Jev 호출 비용 줄이기 검토

## 결론

| 질문 | 답 |
|---|---|
| 기능별 호출을 한 번으로 묶을까 | **보류** — 묶으면 입력 34% 감소, 하지만 실제 대화 기준 하루 약 $0.005 |
| 스킬 폴더를 카테고리로 나눌까 | **했음** — `skills-routed/<category>/<name>/`, 판정은 전체 목록 그대로 |
| 1단계를 카테고리로 판정할까 | **보류** — 카테고리를 잘못 고르면 그 안의 스킬이 후보에서 빠짐 |
| 1단계 설명을 줄일까 (v5 120자) | **보류** — precision 0.895로 v4 0.922보다 낮음, v4 유지 |
| 스킬 설명 앞에 판정 단서 두기 | **했음** — v4 exact 0.678 → 0.695 |
| 다음 | 호출당 요금이 생기거나 스킬이 100개를 넘으면 아래 Backlog 확인 방법으로 다시 측정 |

## 비용은 어디서 나오나

Jev(`jev-1.14`)는 입력 토큰 100만 개에 $0.042이고 출력은 무료입니다. 4일치 로그 기준입니다.

| 출처 | 비용 | 비고 |
|---|---|---|
| `decision eval` | 56% | 10/18 질문 파일 v1→v3 작업 때 한 번에 몰림 |
| 실제 대화 스킬 선택 | 29% | 1단계 3492토큰, 2단계 1093토큰 |
| 실제 대화 도구 판정 | 7% | pi만 사용 |
| 실제 대화 모델 선택 | 5% | |

실제 대화 비용은 하루 약 $0.02입니다. 어떤 방법이든 아낄 돈의 규모는 하루 몇 원입니다.

## 호출을 묶으면

같은 입력으로 Jev를 직접 불러 잰 값입니다.

| 호출 | 입력 토큰 |
|---|---|
| 모델 선택 질문 4개 | 1580 |
| 스킬 판정 질문 6개 | 1083 |
| 10개를 한 번에 | 1748 |

공통 입력(요청, 대화 발췌, 환경) 한 벌이 약 650토큰이고, 묶으면 그만큼 빠집니다. 걸리는 점은 이렇습니다.

| 걸리는 점 | 내용 |
|---|---|
| 2단계는 못 묶음 | 스킬 선택 2단계는 1단계 결과가 있어야 질문을 만듦 |
| 답이 흔들림 | 같은 입력에서 스킬 확률 0.61 → 0.66, 판정 기준선은 0.5 |
| 실패 전파 | 한 번 실패하면 세 기능이 함께 빠짐 |
| 계약 변경 | 새 엔드포인트, 두 클라이언트, CONTRACTS.md, 버전·캐시·평가가 묶임 |

## 설명 길이와 판정 단서

1단계는 후보 설명을 `chooseDescriptionChars`에서 자릅니다.

| 버전 | 설명 | exact | recall | precision |
|---|---|---|---|---|
| v4 (260자) | 원문 | 0.678 | 0.880 | 0.921 |
| v5 (120자) | 원문 | 0.627 | 0.871 | 0.881 |
| v4 (260자) | 앞에 단서 | **0.695** | 0.880 | **0.922** |
| v5 (120자) | 앞에 단서 | 0.695 | 0.883 | 0.895 |

원문을 자르면 "당근 시세", "Reddit 수집"처럼 단서가 뒤에 있던 문제를 놓쳤습니다. 단서를 앞으로 옮기자 대부분 회복했습니다. 앞부분을 너무 넓게 쓰면(`any Svelte code`, `규칙`) 엉뚱한 프롬프트에도 붙어서 precision이 떨어졌습니다. 이 교훈은 `write-a-skill`과 `write-a-rule`의 description 항목에 적었습니다.

## Backlog

- **호출 묶기** — 다시 볼 조건: Jev가 호출당 요금을 받거나, 무료 SKU에서 429가 잦을 때. 확인: `~/.local/state/decision/log-*.jsonl`에서 `skipped`에 429가 하루 10건 이상인지 봅니다.
- **v5 승격** — 다시 볼 조건: 설명을 더 다듬은 뒤. 확인: `bun main.ts eval --feature find_skill --version v5 --all`과 v4를 각각 2회씩 돌려, v5 precision이 v4의 실행 간 흔들림(0.917~0.922) 안에 드는지 봅니다.
- **카테고리 1단계 판정** — 다시 볼 조건: 스킬이 100개를 넘을 때. 확인: 카테고리만 묻는 질문 파일을 만들어 평가 59문제에서 recall이 v4 이상인지 봅니다.
- **평가 결과 재사용** — 같은 질문 파일 버전과 같은 문제면 이전 답을 다시 씁니다. 평가를 자주 돌릴 때만 의미가 있습니다. 확인: 같은 버전을 두 번 돌려 두 번째 실행 비용이 0인지 봅니다.
- **routed 규칙 설명** — 스킬처럼 판정 단서를 앞에 두지 않았습니다. 평가 43번(`provider-errors`)은 v6에서 precision이 떨어졌습니다. 확인: 프로젝트 `rules-routed/` 설명을 고친 뒤 v4 평가를 다시 돌립니다.
- **오차** — 모든 수치는 한 번씩만 돌린 결과입니다.
